01 · The problem

Background

On forensic and controls engagements, data arrives in many forms: bank statements as PDFs, ERP exports, agent sales files, collection registers and emailed spreadsheets. Analysts spent days collecting, reformatting and matching it by hand. This was slow, prone to errors and done differently on each engagement, and it reduced the time left for control testing.

02 · Workflow

n8n workflow

Here is how it worked on the aviation engagements. The workflow matched counter ticket sales against agent records and matched cash collections against the books. The exceptions it produced, such as collections never recorded and excess baggage not charged, became the starting point for control testing instead of something the team found at the end.

03 · Try it

Working demo

This is a small version of the matching and exception rules from the workflow. It uses sample data, not client records. Turn rules on or off to see how the exception list changes.

04 · Data model

Power BI data model

The dashboards had three views. An engagement overview showed reconciliation coverage and open exceptions. An exception register let reviewers filter by rule, entity and value and record what they decided. A controls view linked each exception to the control that should have prevented it, so the audit report could go straight from the data to the root cause.

05 · Results

Results

  • Productivity: preparing engagement data took 25% less time, and that time went into control testing.
  • Assurance: reconciliations cover full populations, so we test every transaction instead of a sample and exceptions can't fall between samples.
  • Consistency: the same rules run on every engagement, and each exception links to its evidence reference for review.
06 · Adoption

Rollout

  1. Phase 1DiagnoseMap data sources and manual preparation steps
  2. Phase 2Buildn8n ingestion, matching and exception rules
  3. Phase 3DeployPower BI model and a live engagement pilot
  4. Phase 4EmbedDocumentation, handover and rule tuning
  1. Start with one real engagementBuilt the first workflow on a live engagement, so the time saved was measured on real work.
  2. Show managers the exceptionsWalked managers through the exception register and how each flag ties back to a control finding.
  3. Write it downDocumented each workflow's inputs, rules and outputs so other analysts can reuse it independently.
  4. Improve from feedbackAdded and adjusted rules based on reviewers' decisions, which reduced false positives over time.

Key takeaways

  1. Automating data preparation gives more time for control testing.
  2. Rules run on the full population catch exceptions that samples can miss.
  3. A live pilot and clear documentation helped the team start using the workflows.
