Executive Summary

Situation

Client data on forensic and controls engagements came in many formats: PDFs, ERP exports, registers and spreadsheets.

Challenge

Collecting and matching this data by hand slowed every engagement and left less time for testing.

01

Background

On forensic and controls engagements, data arrives in many forms: bank statements as PDFs, ERP exports, agent sales files, collection registers and emailed spreadsheets. Analysts spent days collecting, reformatting and matching it by hand. This was slow, prone to errors and done differently on each engagement, and it reduced the time left for control testing.

02

n8n Workflow

The same workflow pattern is used for other reconciliations, such as sales records against agent records, by changing the source files and the matching keys. Unmatched items then become the starting point for control testing rather than something found at the end.

03

Working Demo

This is a smaller version of the matching and exception rules used in the workflow. It uses sample data, not client records. Turn rules on or off to see how the exception list changes.

04

Power BI Data Model

The dashboards had three views. An engagement overview showed reconciliation coverage and open exceptions. An exception register let reviewers filter by rule, entity and value and record what they decided. A controls view linked each exception to the control that should have prevented it, so the audit report could go straight from the data to the root cause.

05

Results

  • Productivity: audit data was pulled and reconciled 25% faster, and the time saved went into control testing.
  • Assurance: reconciliations cover full populations, so every transaction is tested instead of a sample and exceptions cannot fall between samples.
  • Consistency: the same rules run on every engagement, and each exception links to its evidence reference for review.
06

  4. Improved the rules from feedbackAdded and adjusted rules based on reviewers' decisions on each exception.

Key Takeaways

  1. Automating data preparation gives more time for control testing.
  2. Rules run on the full population catch exceptions that samples can miss.
  3. A live pilot and clear documentation helped the team start using the workflows.
